# Changelog

All notable changes to **aflt** / AgentFleet are documented here.
Versions follow [Semantic Versioning](https://semver.org/); see [RELEASING.md](RELEASING.md).

## Unreleased

- **Loop runner loose-end fixes (hello-aflt follow-up)** — Copilot `plan-next` headless runs now always receive a scoped write permission for exactly `$AGENTFLEET_HOME/loops/<name>/plan-next.json` (plus the loop state dir add-dir), with argv coverage in tests. `runner.lock` now records spawned child pids/pgids; `loop run` / `loop resume` clear stale dead-pid locks and reap only lock-recorded children (no pattern kills), with fake-process tests. `aflt loop run`/`resume` now execute through a detached loop-runner process group (`setsid` style) to survive parent-shell teardown.
- **Space/home precedence warning** — precedence is explicit and documented: `AGENTFLEET_HOME` decides directories, `--space`/`AFLT_SPACE` decides tracked space name when home is not explicit. When both are set and conflict, aflt prints a clear warning; tests cover CLI output.
- **Loop validate path warning tuning** — outside-cwd warnings are now suppressed for files under the project's `.agentfleet/` folder (including definition-adjacent `.agentfleet` layouts) while keeping warnings for genuinely external paths.
- **Help behavior hardening** — `--help` / `-h` now prints help and exits `0` with no side effects across subcommands (no sessions/files/engine spawn); coverage walks top-level and nested subcommands in a hermetic temp home with failing engine stubs.
- **hello-aflt is from-scratch by default** — `examples/loops/hello-aflt/` is now the docs-only seed (`install.sh`, `seed/.agentfleet/loop.json`, in-project checks). The old scaffold-copy loop moved to `examples/loops/hello-aflt-seeded/` (`seed-m0.js`, `m0-seed/`). Removed `examples/loops/hello-aflt-scratch/` (folded into hello-aflt). Project id is `hello-aflt`; M5a prompts no longer name external repos. Added `scripts/hello-aflt-smoke.sh` (install → validate → foreground loop; bash `-n` only in CI). Docs, tests, and tile-dungeon eval tier copy the seed before `loop run .agentfleet/loop.json`.
- **Idle timeout for engine runs** — a loop phase whose engine prints nothing and changes no file for `idleTimeoutSec` (default 1200 s; loop, phase or `AFLT_LOOP_IDLE_TIMEOUT_SEC`; `0` = off) is stopped with its whole process tree (a live run hung 30 min on a shell tool waiting on stdin) and counts as a timed-out attempt (fix attempt or fail).
- **Loops UI: last activity and improve round** — `/api/loops` and `loop status --json` add `lastActivityAt` / `lastActivitySource` and `round` (`current`, `last`, `number`, `total`); the dashboard shows "Last activity" and the running improve round instead of "plan-next running".
- **`aflt init --isolated` checks `AGENTFLEET_HOME`** — when it is set and is not the space's home it overrides `--space` (state lands elsewhere); this is now an isolation warning (`fleet-home-override`).
- **Space ports never clash with a running dashboard** — `aflt space create` / `aflt init` skip ports something is listening on now (a quick local probe; `AFLT_NO_PORT_PROBE=1` turns it off) and ports of dashboards served for any space, including spaces with no `config.json`: `dashboard --serve` records its port in `<space>/dashboard-serve.json`, ignored once that process exits.
- **hello-aflt-scratch keeps everything inside the project** — the loop moved into the seed: `seed/.agentfleet/loop.json`, `seed/.agentfleet/prompts/`, and the check tooling `seed/.agentfleet/checks/m0-check.cjs` and `improve-gate.js` (a copy of hello-aflt's gate; the planner uses `node .agentfleet/checks/improve-gate.cjs` instead of `../hello-aflt/improve-gate.js`). Copy the seed into an empty folder, commit, and run `aflt loop run .agentfleet/loop.json` (`workdir.mode: "project"`, `.agentfleet/**` protected). `seed-docs` now checks the repo holds only the seed instead of copying docs in. The checks are `.cjs` so they still run once the game's `package.json` sets `"type": "module"` (a live run hit this: the agent added `.agentfleet/package.json` and tripped the protected path), and the repo `.gitignore` no longer hides the seed's `.agentfleet/`. Prompts no longer name folders outside the project. Still no game code or HTML in the seed.
- **`aflt init` and `aflt loop init`** — `aflt init <name>` creates a project folder, `git init`, a space and starter `SPEC.md` / `AGENTS.md` / `.agentfleet.json` (TTY questions or `--yes` + flags); it refuses a folder with files beyond the seed docs unless `--existing` / `--force`. `aflt loop init` drafts `.agentfleet/loop.json` and per-phase prompts from the docs with a headless engine (Cursor `composer-2.5` / `gpt-5.3-codex`, Copilot `auto` / `claude-sonnet-5.5` by default) following `templates/loop-guide.md`; the draft must pass `loop validate` and a checks policy (M0 builds tests + eval, real checks only, checks inside the project, gate after M0, budget caps, plan-next `force`), with up to two repairs. It appends an `aflt loop` section to `AGENTS.md`, saves a dashboard copy with project-relative prompt paths, and sets `workdir.mode: "project"`. Tutorial: [docs/tutorial/14-new-project.md](docs/tutorial/14-new-project.md). (`aflt new` already creates sessions, so the project command is `init`.)
- **Approval gate shows the cost so far** — `state.gate.costSoFar`, the history line, `aflt loop status` (`cost so far: …`, list view `cost=…`), a dashboard banner and the `loop.gate.waiting` payload (`costSoFar`, `costKnown`, `credits`, `usd`, `activeHours`, `totalTokens`, `runsUsed`). Cursor says “cost unknown”.
- **`improveModel`** — improve rounds inserted by plan-next did not inherit the planner's `model`; they fell through to the loop model chain. `improveModel` (definition or plan-next phase) now sets their model; the planner prompt names it.
- **`workdir.mode: "project"`** — a loop can run in its own clean, non-empty project repo that holds the definition.
- **Loops never depend on outside files** — starting a loop copies each `promptFile` into `loops/<name>/prompts/` and check scripts outside the project (with their folder) into `loops/<name>/files/`; resume reads the copies. A loop saved before this whose prompt file is gone now fails with a clear message. `loop validate` warns about prompt files and check paths outside the project; saved definitions store project prompts relative to the project. Planned improve rounds whose checks climb out of the project are rejected, and the planner and fix prompts tell agents to stay inside it.
- **Isolation checks** — `aflt init` / `aflt loop init` warn about a parent git repo, parent or global instruction files, a shared or default space, and a shared memory repo; `--isolated` makes them errors.
- **Dashboard loop editor** — model field; read-only type / promptFile / improveModel line; edits keep fields the form has no input for; gate banner with the cost so far.

The graph / history / sessions shots now come from the `scratch-composer` and `cmp-copilot-claude-sonnet-5.5` spaces (home paths shown as `~`; every image ≤ 210 KB). 887 tests: 886 passing, 1 skipped.

Their summaries now get `credits` / `usd` from the session's per-call usage records (`making-of.withPerCallCredits`, read-only and mtime-cached; `usage-summary.json` and `state.json` are never rewritten). Loop usage is recomputed at read time from each phase session's turns (de-duplicated, mtime-cached, never written back), so loops recorded before the double-count fix show corrected totals: the Copilot Sonnet hello-aflt run's stored 10.4M tokens is now 6.1M, and the detail adds a note with the stored figure. Recent, History feed entries, timeline marker tooltips and labels, session **last used** / project **last activity**, the task-completion stamp and the snapshot meta line now use `formatLocalDateTime` (browser zone plus a short label, e.g. `2026-11-24 14:37:01 EST`). The Loops detail adds **Started** / **Updated** rows in local time. The making-of page no longer hard-codes America/New_York: its times use the viewer's zone with a short label. JSON APIs keep ISO UTC; the server-rendered `--snapshot` SVG stamp stays ET. Coverage in `test/dashboard-local-time.test.js`.
- **Dashboard Loops: Stop is neutral once a loop finishes** — the Stop button was always the red destructive action, even on a completed loop. For a completed / failed / stopped loop with no live runner it is now a neutral, disabled button (“Loop is completed; nothing to stop”), and Pause is disabled too; Resume, Edit and Making of stay available. Running, pending, waiting, paused and needs-human loops keep the red Stop. Coverage in `test/dashboard-loop-stop.test.js`.
- **Loop hours count active run time, not idle gaps** — `budget.hoursUsed`, `elapsedMs` and the Loops “Elapsed” / budget hours now sum run segments (start/resume → completed, failed, stopped, paused, gate wait or needs-human) instead of `now − startedAt`, so a loop that completes and is resumed hours later no longer counts the gap (the scratch-composer `hello-aflt-scratch` run showed 3.108 h for ~21 min of work; it now shows 0.348 h). `budget.maxHours` is enforced on the same number. New state keeps `activeMs` + `runSegmentStartedAt`; older state files are reconstructed from loop history at read time and are not rewritten until the loop runs again; a segment left open by a crashed runner is closed at its last update. `loop status --json` adds `wallElapsedMs`. Coverage in `test/loop-active-time.test.js`.

- **Loop human escalation (`needs_human`)** — optional `escalation: { afterFailedRounds?: 3, event?: "loop.needs_human" }`. Terminal phase failures (exhausted fix attempts, non-retryable engine errors, protected-path violations, commit-gate refusal) set `status=needs_human` instead of `failed`, write `loops/<name>/needs-human.json`, emit `loop.needs_human` and `loop.gate.waiting` with a diagnostic bundle, and resume via `aflt loop resume`. Plan-next improve loops track consecutive failed rounds toward `afterFailedRounds`. Hermetic coverage in `test/loop-escalation.test.js`.
- **Loop verification stamps and commit gate** — a definition can set `commitGate: { mode: "off" | "observe" | "enforce", trailer?: "Verified-by", requireTiers?: [...] }` (default off: today's `aflt loop NAME phase ID passed` commit, unchanged). Each phase now records verification results on `phases[id].verification[]` (the eval as tier `eval` with command, exit code, duration and parsed `node:test` counts; `recordVerification(phaseState, { tier, ok, summary })` is exported for tier checks). With a gate on, `onPass: "commit"` (and a merge commit created by `onPass: "merge"`) gets `Verified-by: npm test 681/681 (1 skipped); tier2 smoke ok` (or `none`) and `Aflt-Loop: <loop> phase <id> attempt <n>, engine <e>[, model <m>]` trailers using the repo's own git author. `observe` warns (`loop.commit_gate.warning` history + stderr) on a missing required tier or a tree still dirty after the commit and still commits; `enforce` refuses (phase fails with no fix attempt, `loop.commit_gate.refused`, explanatory `lastError`) unless every `requireTiers` entry is recorded ok and the tree is clean afterward. Covered in `test/loop-commit-gate.test.js`.
- **`aflt doctor --strict`** — preflight on top of the read-only checks: engine CLIs on PATH (plus a hint when `~/.local/bin/cursor-agent` exists but `~/.local/bin` is not on PATH), per-engine sign-in probe (`cursor-agent status`; Copilot/OpenCode have no probe and report `unknown (no probe)` as a warning), notify config (warning; `--strict --notify` does a live `aflt notify test` round trip), a free-port test-bind (`--port N` checks that port, otherwise the default 8787 is only reported and an ephemeral port is test-bound), and `--loop <file>` to show the loop workdir inspection and engine CLIs. Checks are `ok` / `warn` / `fail` (`status` in `--json`); `--strict` exits 1 only on a `fail`. A missing or signed-out *default* engine (or an engine the `--loop` uses without a failover list) is a failure; other engines only warn.
- **Loop engine failover (`engines`)** — a definition can set `engines: ["copilot", "cursor", "opencode"]`. Primary precedence: phase `engine` > definition `engine` > `AGENTFLEET_ENGINE` > `engines[0]` > config > cursor. When a worker run hits a non-retryable infrastructure error (`cli_missing`, `auth_required`, `usage_limit`, `rate_limit`, `model_unavailable`), the phase reruns the same attempt (not a fix attempt) on the next installed engine with an engine-specific session `<session>-<engine>`; a failing eval never fails over, and with no engines left the phase fails as before. The engine used is stored on the phase (`engine`, `failovers[]`), in history, and in a `loop.engine.failover` notify event (`engine`, `fromEngine`, `errorKind`). A missing primary CLI no longer refuses a live run when another listed engine is installed. Covered in `test/loop-engine-failover.test.js`.
- **`self-improve.json` follows the default engine** — the example no longer pins `"engine": "cursor"` on the definition and every phase, so `AGENTFLEET_ENGINE` / config / the builtin default decide (same order as new sessions). Covered in `test/eval-e3.test.js`.
- **Loop `protected` paths (no self-grading)** — a definition can set `protected: { "paths": [globs], "source"?: "base" }` (plus optional per-phase `protected.paths`). The runner records the base commit (`state.baseSha`, `phases[id].baseSha`) at loop and phase start; after the worker run and before the eval it diffs the loop cwd against that base (committed, staged, unstaged and untracked files). A match fails the phase immediately with the offending paths in `lastError` — no fix attempts, `loop.phase.protected_violation` history event, and `protectedViolation: [paths]` on the `loop.phase.failed` / `loop.failed` notify payloads. Globs support exact paths, directory prefixes, `*`, `?` and `**`. `lib/protected-paths.js` also exports `materializeBaseTree(cwd, baseSha, dest?)` (detached throwaway `git worktree` with `cleanup()`) for running evals from the base commit. Definitions without `protected` are unchanged. Hermetic coverage in `test/loop-protected-paths.test.js`.
- **Loop `workdir.mode: "worktree"`** — a loop definition can set `workdir: { "mode": "worktree", "base"?, "path"?, "branch"? }` so the cwd guard accepts a clean, non-empty git worktree (ideally a linked `git worktree add` checkout) instead of requiring an empty repo or `--allow-existing`. It still refuses a dirty tree, a non-git folder, and the running aflt package root (or anything inside it), with errors that suggest `git worktree add <path> <base>`. Default mode is `"fresh"` (the existing strict guard); unknown modes fail validation. `--dry-run` prints a `workdir:` line (and JSON `workdir`) with the inspection. `aflt loop run --create-worktree` runs `git worktree add -b <branch|aflt-self-<timestamp>> <path> <base>` for a missing `workdir.path` from the definition file's repo (never implicit; dry-run only reports it). Hermetic coverage in `test/loop-workdir-worktree.test.js`.
- **Clearer loop cwd guard** — `aflt loop run` on a fresh non-git directory now says to `git init` it (loops commit each passed phase) or pass `--allow-existing`; the guard itself is unchanged.
- **Dashboard Loops polish** — `/api/loops` and `/api/loops/:name` now report `engine` / `model` (definition → first phase → worker sessions → env/config default) and treat a loop with a live runner lock pid as `active` (in-process `aflt loop run`, with `runnerPid`). Worker sessions of finished/failed loops now count as Completed / Failed in the stats and graph instead of staying Idle. The dashboard opens on the Loops tab (selecting the live loop) when loops exist, serves `/favicon.ico`, re-syncs the selected loop detail pane (phase, runs, status, elapsed) from every live update without losing scroll, and the loops footer hint no longer overlaps the panels.
- **Loops fail fast on non-retryable engine errors** — `lib/engine-errors.js` classifies failed worker output (`usage_limit`, `rate_limit`, `model_unavailable`, `auth_required`, `cli_missing`) for Cursor/Copilot/OpenCode. A matching phase no longer burns `maxFixAttempts`: it fails immediately with the real error line (not "agent exited 1") in `lastError` and history, and `loop.phase.failed` / `loop.failed` notify payloads gain `errorKind` + `nonRetryable: true`. Copilot's unpinned-model `auto` fallback still retries first; a missing engine binary is now a failed run (exit 127) instead of a thrown error. Hermetic coverage in `test/engine-errors.test.js`, `test/loop-engine-errors.test.js`.
- **Copilot loop `plan-next` can write its state file** — `plan-next` phases now pass `--add-dir <loops/<name>>` and a scoped `--allow-tool=write(<loops/<name>/plan-next.json>)` to Copilot (no `--allow-all-paths`), so non-interactive runs no longer fail with "Permission denied" / "plan-next file missing" when the loop state dir is outside the worker `-C` cwd. Other phase types and Cursor/OpenCode argv are unchanged. Hermetic coverage in `test/loop-copilot-safety.test.js`.
